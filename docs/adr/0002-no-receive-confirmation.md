# 免确认自动接收

在「只在自己家里的私有 WiFi 使用」这一前提下，接收端不对任何投递弹确认，也不做首次配对，收到即直接落入收件目录。用户明确要求「不用确认」，而每次确认或首次配对都会增加交互步骤并引入身份与密钥管理。

**Considered Options**

- 每次确认 / 首次配对后信任（TOFU）：更安全，但需要身份标识、配对状态持久化和撤销入口，且与「不用确认」直接冲突。

**Consequences**

- 同一子网内任何设备都能向收件目录写入或读取传输内容，安全性完全由网络边界承担。换到公共或办公 WiFi 时这个前提不成立，届时必须在 UI 上明示或改为确认模式。
- 因此写入范围必须收敛到单一收件目录，禁止覆盖同名文件、禁止路径穿越，且不做覆盖式重命名。
